# create-github-issue

계획을 **grill**(안 정해진 결정을 한 문항씩 해소)로 명확히 한 뒤, **vertical slice** 단위 이슈로 쪼개 **승인 게이트**를 거쳐 발행한다. 작업이 크면 에픽 1개 + **sub-issue** N개로 묶는다.

제목 규칙, 본문 템플릿, 레이블, gh 명령은 `rules/GUIDE.md` 에 있다. 필요한 섹션만 골라 읽고 여기 본문에 옮겨 적지 않는다.

---

## 1단계: 맥락 수집

- 인자가 이슈 번호나 URL이면 `gh issue view` 로 본문과 댓글을 읽는다.
- 코드베이스를 탐색해 무엇을 어디에 만들지 후보를 잡는다. 제목과 본문은 코드의 실제 용어를 쓴다.
- `gh issue list --state open` 으로 **같은 내용의 이슈가 이미 있는지** 확인한다. 있으면 새로 만들지 않고 사용자에게 알린다.

> **완료 기준**: 무엇을 만들지 말할 수 있고, 중복 이슈가 없음을 확인했다.

## 2단계: Grill

안 정해진 결정만 **한 문항씩** 묻는다. 질문마다 **추천답**을 함께 낸다.

- 코드베이스 탐색으로 답할 수 있으면 묻지 않고 탐색해서 자답한다.
- 대화 맥락에 이미 답이 있으면 건너뛴다.

해소할 분기:

- **유형**: Feat / Fix / Bug / Refactor / Hotfix / Epic 중 무엇인가 (구분 기준은 GUIDE.md 의 "이슈 제목 규칙")
- **범위**: 이슈 하나로 끝나는가, 여러 슬라이스로 쪼개야 하는가
- **완료 조건**: 무엇이 되면 끝인가. 체크 가능한 문장으로 적을 수 있는가

> **완료 기준**: 위 분기가 해소되어 제목 후보와 완료 조건을 적을 수 있다.

## 3단계: Vertical slice 초안

이슈 하나로 안 끝나면 **tracer bullet** 으로 쪼갠다.

- 각 슬라이스는 한 레이어가 아니라 끝에서 끝까지 관통하는 **얇고 완결된 경로**다. 그 자체로 검증할 수 있어야 한다.
- 두꺼운 슬라이스 몇 개보다 얇은 슬라이스 여럿을 고른다.
- 에픽으로 묶을 크기면 에픽 1개 + sub-issue N개로 잡는다.
- 슬라이스 사이의 선행 의존(blocked by)을 정한다.

> **완료 기준**: 슬라이스 목록과 의존 순서, 에픽과 sub-issue 관계가 정해졌다.

## 4단계: 승인 게이트

발행 **전에** 만들 이슈를 번호 목록으로 보여주고 승인받는다. 항목마다 적는다.

- **제목** (GUIDE.md 의 "이슈 제목 규칙"을 지킨다)
- **레이블**
- **관계**: 에픽인가 sub-issue 인가
- **Blocked by**: 선행 슬라이스. 없으면 "없음"
- **완료 조건**: 체크박스 항목

사용자에게 묻는다. 쪼갠 단위가 맞는가, 의존 순서가 맞는가, 합치거나 더 쪼갤 것이 있는가.

> **완료 기준**: 사용자가 목록을 명시적으로 승인했다. 승인 전에는 발행하지 않는다.

## 5단계: 발행

승인된 순서대로 발행한다. 에픽과 blocker 를 먼저 만든다.

- GUIDE.md 의 "공통 템플릿"을 채운다. 레이블은 `--label` 로 직접 지정한다. 이 레포에는 `labeler.yml` 이 없어 자동 부여가 없다.
- sub-issue 는 에픽과 자식을 모두 만든 뒤 GUIDE.md 의 sub-issue 연결 명령으로 붙인다.
- blocked by 는 실제 이슈 번호로 본문에 적는다. 그래서 에픽과 blocker 를 먼저 발행한다.
- 인자로 받은 기존 이슈는 닫거나 고치지 않는다.

> **완료 기준**: 만든 이슈의 번호와 URL, sub-issue 연결 결과를 출력했다.

---

## 주의사항

- `gh` CLI 가 있어야 한다. 인증은 `gh auth login` 으로 한다.
- 이 레포는 개인 계정이다. `gh` 명령 전에 GUIDE.md 의 토큰 지정 줄을 먼저 실행한다.
